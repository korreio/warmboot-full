# Warmboot self-adoption disposition

Owner: documentation architecture owner. This ledger shows how Warmboot Full is a
first-class consumer of its portable document roles without turning the generic
templates into a second root authority.

| Portable role/source | Disposition | Root owner/adaptation | Evidence and recurring cost | Revisit/deletion trigger |
|---|---|---|---|---|
| Provider loaders | `MERGE INTO EXISTING` | Root `AGENTS.md`/`CLAUDE.md` remain thin pointers to `WARMBOOT.md`. | Loader/path tests; two tiny files. | Merge further if a proved provider can discover one file natively. |
| Project README | `MERGE INTO EXISTING` | Root `README.md` owns human quick starts and consumer overview. | README prompt assertions/link scan. | Split only if distinct audiences cannot navigate one file. |
| Role index | `ADOPT` | Root `ROLE-INDEX.md` routes maintainer authorities; the target-facing role-selection table lives in `docs/documentation-architecture.md`. | Manual route/link checks. | Remove a route when its owning role is retired. |
| Documentation guide | `MERGE INTO EXISTING` | `MAINTAINING.md`, role index and system map divide takeover, routing and ownership. | Fresh planner must find all three. | Consolidate if the division causes reproduced ambiguity. |
| System map | `ADOPT` | `docs/maintainer-system-map.md` owns repository planes/components. | Architecture review and link scan. | Update with owner/dependency changes. |
| Engineering standards | `ADOPT` | `docs/engineering-standards.md` specializes portable rigor for Warmboot, including target-native human inspectability and optional locally calibrated SLOC/complexity triage. | Review plus closing set and human navigation/rationale lens; no count target. | Supersede only with proved simpler/equal control. |
| Testing guide | `ADOPT` | `docs/testing.md` owns focused/closing/live gates, assertion/fixture/skip quality and limits. | Commands, tier-labelled acceptance receipts and non-author review. | Change with test surface, oracle provenance, skip consequence or evidence tier. |
| Invariant ledger | `ADOPT` | `docs/invariants.md` records actual repository states/owners/recovery. | Oracle/helper/release/source guards. | Retire an invariant only after its recurrence path is impossible. |
| Changelog | `ADOPT` | Root `CHANGELOG.md` owns user-visible toolkit change. | Same-change review/release reconciliation. | Never delete released history. |
| Observed-defect ledger | `ADOPT` | Root `BUGFIXES.md` owns reproduced causal history only. | Each entry has recurrence and retirement evidence. | Retire executable tax when entry's deletion condition is proved. |
| Lightweight decisions/full ADR | `MERGE INTO EXISTING` | Durable choices use `docs/adr/`; small current choices may stay in the active plan. | ADR status/plan review. | Promote only when a decision outlives the task. |
| Research brief/study | `CITE ONLY` | Relevant local rationale and current source catalogues are read on changes; no empty root brief. | Source freshness and task citation. | `ADOPT` a new study only for a real unresolved choice. |
| Active plan | `MERGE INTO EXISTING` | `docs/plans/warmboot-build-plan.md` remains the concise current authority; closed evidence is archived in Git, not in the tree. | Status/evidence review. | Keep one active path; archive closed receipts without creating a second plan. |
| Current quality-control loop | `MERGE INTO EXISTING` | The named current task/backlog owns the current assessment/action loop; no permanent scorecard file or grade is introduced. | Applicable architecture/source/test/security/privacy/operations evidence, explicit unknowns, owned next step and human/non-author challenge. | Split into a dedicated assessment only after the merged route causes a reproduced findability/ownership failure. |
| Review brief | `OMIT` as standing file | Review scope/verdict belongs to the active task/evidence record. | Prevents an empty permanent review form. | Adopt only if recurring ambiguity proves a stable brief necessary. |
| Runbook | `MERGE INTO EXISTING` | `docs/source-refresh.md` and `docs/release.md` are earned hazard-specific runbooks. | Dry-run/oracle and release receipts. | Delete only when the external boundary disappears. |
| Subtree overlay | `OMIT` | No root subtree currently needs a different instruction authority. | Root loader/path scan. | Adopt after a real subtree precedence conflict, not pre-emptively. |
| Task/handoff aids | `MERGE INTO EXISTING` | Reuse current task/plan and routine by-reference freshness receipts; material addenda revise that task and impact-analyze assignments/evidence; no permanent blank root copy and no handoff-carried rules/authority/authorship. | Stale-recovery probe, affected/unaffected scope fixture, and routine-handoff/exceptional-rotation semantic canary. | Adopt a root artifact only when no useful current owner exists. |
| Optional capability library | `ADOPT` as opt-in discovery only | `templates/capabilities/` and its manifest are owned by the capability-library maintainer; target-native owners survive adoption. Ordinary use is relevant-card selective; all twelve are acceptance-audit coverage. It is not helper-managed payload or standing target policy. | Twelve-card manifest, hash, link, rights and containment checks; managed-inventory and capability-leakage checks; no-bytecode cold target and the cold outsider gate. Target upkeep applies only to selected material. | Revisit a card when it no longer changes a target decision. Executable integration requires observed consumer need and an architecture decision. |
| Capability source catalog | `CITE ONLY` | `docs/capability-sources.json` binds current local rationale and inherited rights. | Strict JSON, digest/mapping/rights/containment checks and matched final outsider receipts. | Refresh when rationale or rights change; remove a row only with its owning card. |
| Shipped sample `templates/project-docs/documentation-guide.md` (no root twin) | `OMIT` | No root `docs/documentation-guide.md` is created. `docs/documentation-architecture.md` is the single normative home for the role model, the four dispositions, precedence and lifecycle; a second guide would duplicate that contract. | Single-definition check: one home for the role table and the disposition vocabulary. | `ADOPT` only if the merged contract grows past what a fresh maintainer can read in one pass, and then split by audience rather than by copying the sample. |
| Shipped sample `templates/project-docs/system-map.md` (no root twin) | `OMIT` | No root `docs/system-map.md` is created. `docs/maintainer-system-map.md` already owns this repository's planes, components, owners and non-goals in a maintainer-shaped form the generic target sample does not fit. | Directory scan: the sample ships for targets and has no root twin to keep synchronized. | `ADOPT` a second map only if a non-maintainer navigation audience appears that the maintainer map cannot serve. |

When a root rule changes, assess the corresponding portable template in the same
change: update both when the lesson is provider/project-neutral; update only root when
it is Warmboot-specific and record why. When a portable template changes, assess this
root adoption and its example/tests in the same change. Retained samples remain optional teaching inputs, not target authority.
